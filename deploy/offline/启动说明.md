# 校园快递收发系统 · 离线部署包

> 版本：v1.0.0（对应源码 commit `e3c2a9b`）
> 适用：无外网或不便拉取镜像的环境，解压后即可启动

## 一、包内文件

| 文件 | 说明 |
| --- | --- |
| `images.tar.gz` | 四个镜像的离线包（334 MB，解压后约 1.6 GB） |
| `docker-compose.yml` | 离线编排文件，直接引用导入的镜像，不需要构建 |
| `.env` | 环境变量（已生成随机数据库密码与 JWT 密钥） |
| `mysql-init/01-init.sql` | MySQL 首次启动的字符集与时区初始化 |
| `start.sh` | macOS / Linux 一键启动脚本 |
| `start.bat` | Windows 一键启动脚本 |
| `启动说明.md` | 本文件 |

镜像清单：

- `campus-express/backend:1.0.0`（FastAPI 后端）
- `campus-express/frontend:1.0.0`（Nginx + Vue 构建产物）
- `mysql:8.0`
- `redis:7-alpine`

## 二、环境要求

- Docker Engine 24+ 或 Docker Desktop 24+，且带 Compose v2
  自检命令：`docker compose version` 能输出版本号
- 可用内存 ≥ 2 GB，磁盘 ≥ 5 GB
- 端口 `80`、`8000` 未被占用（被占用时见第五节）

## 三、启动（三步）

在解压后的目录内执行：

```bash
docker load -i images.tar.gz   # 1. 导入镜像
docker compose up -d           # 2. 启动四个服务
docker compose ps              # 3. 确认状态
```

也可以直接运行脚本：

- Windows：双击 `start.bat`
- macOS / Linux：`bash start.sh`

首次启动时后端会自动执行数据库迁移并写入演示数据，通常 30–60 秒完成；四个服务全部 `healthy` 即就绪。

## 五、端口与配置

端口写在 `.env` 中，按需修改后重新 `docker compose up -d` 生效：

```env
FRONTEND_PORT=80      # 前端页面端口
BACKEND_PORT=8000     # 后端接口端口
```

数据库密码与 `JWT_SECRET` 已随机生成；如需更换，修改 `.env` 后必须执行 `docker compose down -v` 再启动（否则旧密码的数据库卷会与之不匹配）。

> **密码字符限制**：`MYSQL_PASSWORD` / `MYSQL_ROOT_PASSWORD` 请只使用字母与数字。这两个值会被拼进
> `mysql+pymysql://用户:密码@mysql:3306/库名` 连接串，若包含 `@`、`:`、`/`、`#`、`?` 等字符会被当作
> URL 分隔符解析，后端将报 `Can't connect to MySQL server`。

## 六、日常运维命令

```bash
docker compose stop            # 停止（保留容器与数据）
docker compose start           # 再次启动
docker compose down            # 删除容器（数据卷保留）
docker compose down -v         # 彻底重置：连数据一起删除，下次启动重新灌演示数据
docker compose logs -f backend # 查看后端日志
docker compose ps              # 查看健康状态
```

数据存放于名为 `campus-express_mysql_data` 的 Docker 卷中（由编排文件的顶层 `name` 固定，不会与其他项目冲突）。

## 七、常见问题

1. **`docker load` 提示找不到文件**：确认终端的当前目录是本包解压后的目录。
2. **`docker compose up` 报端口被占用**：80 端口常被 IIS、迅雷、其他 Web 服务占用，改 `.env` 的 `FRONTEND_PORT=8080` 后重试。
3. **后端一直是 `starting`**：执行 `docker compose logs backend` 查看。多为 MySQL 首次初始化未完成（等待 30 秒）或内存不足。
4. **页面能打开但接口 502**：前端会等后端健康后再启动，稍等 20 秒刷新；若持续，查看后端日志。
5. **时间显示与本地差 8 小时**：确认 `.env` 中 `TZ=Asia/Shanghai`，容器内时区由该变量决定。
6. **想恢复初始演示数据**：`docker compose down -v` 后重新 `docker compose up -d`。
