# 部署说明

> 适用版本：v1.0（阶段五完成后）
> 两种启动方式均验证通过：Docker 一键启动、本地开发模式。

## 一、环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Docker Desktop | 24+（实测 29） | 提供 MySQL 8.0 与 Redis 7 |
| Docker Compose | v2 | `docker compose` 子命令 |
| Node.js | 20+（实测 22） | 仅本地开发前端时需要 |
| Python | 3.12+（实测 3.13） | 仅本地开发后端时需要 |
| 浏览器 | Chrome / Edge 最新版 | 推荐 1440×900 以上分辨率 |

端口占用：`80`（前端）、`8000`（后端）、`3306`（MySQL）、`6379`（Redis）。本地开发模式只占用后三个。

## 二、目录结构

```text
Campus_Express/
├── backend/                 # FastAPI 服务（app / alembic / seed）
├── frontend/                # Vue 3 前端（views / router / stores / api）
├── deploy/                  # Docker Compose、MySQL 初始化、环境变量
├── docs/                    # 设计文档、交付物、阶段验收单
├── scripts/                 # 绘图、文档生成、接口冒烟测试
└── README.md
```

## 三、方式一：Docker 一键启动（推荐演示）

```bash
cd Campus_Express
cp deploy/.env.example deploy/.env
docker compose -f deploy/docker-compose.yml up -d --build
```

启动过程：

1. MySQL 8.0 初始化 `campus_express` 库并执行 `deploy/mysql/init/01-init.sql`
2. 后端容器等待 MySQL 健康后执行 `alembic upgrade head`
3. Nginx 托管前端静态文件，并将 `/api` 反向代理到后端

访问：

- 系统首页：<http://localhost>
- 接口文档：<http://localhost:8000/docs>
- 健康检查：<http://localhost/api/v1/health>

演示账号：

| 角色 | 账号 | 密码 |
| --- | --- | --- |
| 管理员 | `admin` | `Admin@123` |
| 工作人员 | `staff01` | `Staff@123` |
| 学生 | `2023010101` | `Student@123` |

首次启动后如需演示数据（驿站、包裹、寄件、公告、通知）：

```bash
docker compose -f deploy/docker-compose.yml exec backend python -m app.seed
```

> 全栈模式下 MySQL、Redis 不对宿主机暴露，避免端口冲突。

## 四、方式二：本地开发模式

```bash
# 1) 只启动数据库与缓存
cp deploy/.env.example deploy/.env
docker compose -f deploy/docker-compose.infra.yml up -d

# 2) 后端
cd backend
python -m venv .venv
.venv/Scripts/activate            # macOS / Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
python -m app.seed
uvicorn app.main:app --reload --port 8000

# 3) 前端（另开终端）
cd frontend
npm install
npm run dev
```

访问 <http://localhost:5173>，Vite 已配置 `/api` 代理到 8000。

> 两种方式共用 `deploy/` 下的数据卷。切换前先停止当前方式：`docker compose ... down`，**不要加 `-v`**，否则数据会被清空。

## 五、方式三：离线包部署（无网络环境）

在已构建镜像的机器上生成离线包：

```bash
python scripts/build_offline_package.py             # 默认版本 1.0.0
python scripts/build_offline_package.py --version 1.0.1
```

产物为 `dist-offline/campus-express-offline-v1.0.0.zip`（约 334 MB），包内结构：

| 文件 | 说明 |
| --- | --- |
| `images.tar.gz` | 四个镜像：backend、frontend、mysql:8.0、redis:7-alpine |
| `docker-compose.yml` | 离线编排，直接引用导入的镜像，无需构建 |
| `.env` | 随机生成的数据库密码与 JWT 密钥 |
| `mysql-init/` | 字符集与时区初始化脚本 |
| `start.sh` / `start.bat` | macOS/Linux 与 Windows 一键启动脚本 |
| `启动说明.md` | 面向使用者的完整操作说明 |

使用方解压后三步启动：

```bash
unzip campus-express-offline-v1.0.0.zip
cd campus-express-offline-v1.0.0
docker load -i images.tar.gz
docker compose up -d
```

注意事项：

- 离线编排的 `container_name` 固定为 `campus-*`、项目名固定为 `campus-express`，**不能与方式一同时运行**
- 两种方式使用独立数据卷（`deploy_mysql_data` 与 `campus-express_mysql_data`），互不影响
- `.env` 中数据库密码只能用字母数字，含 `@ : / # ?` 会破坏 `DATABASE_URL` 解析

## 六、环境变量

`deploy/.env`（Docker）与 `backend/.env`（本地）字段一致：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MYSQL_ROOT_PASSWORD` | `root_pass` | MySQL root 密码 |
| `MYSQL_DATABASE` | `campus_express` | 数据库名 |
| `MYSQL_USER` / `MYSQL_PASSWORD` | `campus` / `campus_pass` | 业务账号 |
| `DATABASE_URL` | `mysql+pymysql://campus:campus_pass@...` | 后端连接串 |
| `REDIS_URL` | `redis://.../0` | 缓存与登录锁定 |
| `JWT_SECRET` | 示例值 | **生产环境必须替换** |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `120` | 访问令牌有效期 |
| `REFRESH_TOKEN_EXPIRE_DAYS` | `7` | 刷新令牌有效期 |
| `PICKUP_CODE_EXPIRE_DAYS` | `7` | 取件码有效期 |
| `OVERDUE_THRESHOLD_DAYS` | `3` | 超期阈值 |

## 七、数据库迁移与重置

```bash
# 查看当前版本
cd backend && alembic current

# 升级到最新
alembic upgrade head

# 回退一个版本
alembic downgrade -1

# 清空数据重新开始（谨慎）
docker compose -f deploy/docker-compose.yml down -v
docker compose -f deploy/docker-compose.yml up -d --build
```

迁移脚本：`0001` 用户、`0002` 驿站货架、`0003` 包裹取件、`0004` 寄件通知公告、`0005` 异常日志。

## 八、定时任务与日志清理

```bash
# 超期包裹扫描（默认 24 小时内不重复提醒）
docker compose exec backend python -m app.tasks.overdue_scan --dry-run
docker compose exec backend python -m app.tasks.overdue_scan

# 清理 90 天前的操作日志与已读通知（本地开发模式）
python scripts/cleanup_logs.py --days 90 --dry-run
python scripts/cleanup_logs.py --days 90 --with-notifications
```

生产环境可用 cron 每日执行一次：

```cron
0 9 * * * cd /app && python -m app.tasks.overdue_scan
0 3 * * 0 python /app/scripts/cleanup_logs.py --days 90 --with-notifications
```

## 十、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `docker compose build` 卡在拉取 nginx | 网络无法访问 Docker Hub（IPv6 超时） | 配置镜像加速或改用已缓存的 `deploy-frontend` 镜像 |
| 后端启动报 `Can't connect to MySQL` | MySQL 尚未健康 | 等待 20–30 秒，或查看 `docker compose logs mysql` |
| 页面 502 | 后端容器未启动 | `docker compose ps` 检查，`docker compose logs backend` |
| 修改后端代码后接口未变 | `--reload` 在 Windows 偶发未生效 | 手动重启 uvicorn |
| 登录返回 429 | 连续输错 5 次触发锁定 | 等待 15 分钟，或清空 Redis `login:fail:*` |
| 学生访问管理页跳 403 | 角色权限控制生效 | 使用管理员/工作人员账号 |
