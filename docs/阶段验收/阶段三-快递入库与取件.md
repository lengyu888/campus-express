# 阶段三验收：快递入库与取件出库

> 阶段目标：打通收件闭环——运单入库、自动分配格口、生成取件码、双重核验出库、格口释放与取件记录。
> 状态：已验收并提交（commit `4831482`）。

## 一、本阶段完成内容

**数据库**

- 新增 `packages`（包裹）与 `pickup_records`（取件记录）两张表
- Alembic 迁移 `0003_create_packages_pickup_records`
- 唯一约束：`packages.tracking_no`、`(packages.station_id, packages.pickup_code)`、`pickup_records.package_id`
- 外键：`station_id → stations`、`shelf_id → shelves`、`recipient_id / created_by → users`
- 索引：状态、收件人手机号、取件码到期时间、货架、取件时间

**状态机**

```text
入库 → in_stock ──(超过 3 天)──> overdue ──(核验出库)──> picked
                 ├──(登记退回)──> returned
                 └──(登记异常)──> exception
```

`in_stock / overdue` 以 `stored_at` 实时计算，不依赖定时任务；出库时把超期天数写入 `overdue_days`。

**后端接口（11 个）**

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/packages` | 包裹分页查询（状态、驿站、类型、关键字） | 登录用户，学生仅本人 |
| GET | `/packages/summary` | 在库、超期、今日入库/出库等指标 | 工作人员、管理员 |

| GET | `/pickup-records` | 取件记录查询（今日、关键字） | 工作人员、管理员 |

**核心业务规则**

1. 运单号全局唯一，重复入库返回 20001 并附带原包裹 id 与入库时间。
2. 按收件人手机号自动匹配系统账号；未匹配时保留运单收件人姓名。
3. 格口分配：未指定货架时选择「剩余格口最多」的可用货架；全部占满返回 20005。
4. 取件码 6 位数字，驿站内唯一，连续 5 次冲突则回滚并返回 50000。
5. 取件码有效期 7 天；过期后只能人工核验（`verify_type=manual`）。
6. 出库必须同时校验取件码与手机号后四位，任一不符分别返回 20002 / 20003。
7. 出库使用行锁 + 唯一约束双重保障，重复出库返回 20004，格口不会减成负数。
8. 退回、出库都会释放格口；异常件保留格口，暂停出库。
9. 批量入库单条失败不影响其他条目，返回逐条结果。
