# 阶段四验收：寄件、通知与统计报表

> 阶段目标：补齐寄件业务闭环、站内通知与公告、运营统计报表，让系统从「收件工具」变成完整的收发件平台。
> 本阶段代码**尚未提交**，验收通过后再执行 commit。

## 一、本阶段完成内容

**数据库**

- 新增 `shipment_orders`（寄件订单）、`shipment_tracks`（寄件轨迹）
- 新增 `notifications`（站内通知）、`announcements`（公告）
- Alembic 迁移 `0004_create_shipments_notifications`
- 唯一约束：`shipment_orders.order_no`
- 索引：寄件人、状态、`(station_id, status)`；通知 `(user_id, is_read)`；公告 `(status, publish_at)`

**寄件状态机**

```text
pending 待揽收 → accepted 已揽收 → shipped 已发出 → completed 已完成
      └──────────── cancelled 已取消（仅待揽收可取消）
```

每次状态流转都会写入一条轨迹，记录节点、描述、操作人和时间。

**运费规则**

首重 1 kg 8 元，续重每 1 kg 加 2 元，不足 1 kg 按 1 kg 计；下单时按填写重量估算，揽收时按实重重算，工作人员可手动调整。系统不接入在线支付，运费仅记录。

**后端接口（21 个）**

| 模块 | 接口 |
| --- | --- |
| 寄件 | 列表、统计、下单、详情、轨迹、揽收、发出、完成、取消（9 个） |
| 通知 | 列表、未读数、单条已读、全部已读（4 个） |
| 公告 | 列表、发布、修改、下架（4 个） |
| 统计 | 总览、收发趋势、驿站工作量、超期分析（4 个） |

**业务规则**

1. 学生只能看到自己的寄件订单，工作人员与管理员可看全部；越权返回 403。
2. 仅学生可下单，支持按收件人、驿站、重量、物品描述创建订单。
3. 状态流转严格校验，非法流转返回 `30001`；取消仅限待揽收。
4. 揽收时写入实际重量、承运商与运费，并向寄件人推送站内通知。
5. 包裹入库自动向匹配到的收件人推送「包裹已到站」并附取件码；取件成功推送「取件成功」。
6. 通知按用户隔离，支持类型筛选、单条已读、全部已读与未读数。
7. 公告仅管理员可发布，下架为软删除（`status=0`），学生列表只展示已发布。
8. 统计口径：在库为未超期在库件，超期为入库超过 3 天；超期率 = 超期 /（在库 + 超期）。

**演示数据**

- 5 单寄件：待揽收、已揽收、已发出、已完成、已取消各 1 单，轨迹节点齐全
- 2 条公告、6 条站内通知（学生 4 条、工作人员 2 条）

**前端（5 个页面）**

- **我的寄件（学生）**：指标卡、状态分段筛选、订单卡片（驿站 → 收件地址路线）、新建寄件抽屉（实时运费估算）、轨迹抽屉、取消订单
- **寄件处理（工作人员 / 管理员）**：指标卡、状态筛选与搜索、订单表格、揽收弹窗（实重、承运商、运费，自动估算可改）、发出 / 完成确认、轨迹抽屉
- **消息中心（全角色）**：通知 / 公告双 Tab、类型筛选、未读圆点、单条已读、全部已读、公告正文
- **公告管理（管理员）**：公告卡片、发布 / 编辑弹窗、下架与重新发布
- **统计报表（工作人员 / 管理员）**：6 张 KPI、自绘 SVG 收发趋势图（7 / 14 / 30 天）、驿站工作量进度条、超期分布柱状图与超期件列表
- 顶栏铃铛显示未读数（每分钟刷新、路由切换刷新），点击进入消息中心
