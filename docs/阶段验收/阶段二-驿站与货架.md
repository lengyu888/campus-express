# 阶段二验收：驿站与货架管理

> 阶段目标：完成多驿站档案、货架分区与格口容量管理，为阶段三的快递入库提供存放基础。
> 本阶段代码**尚未提交**，验收通过后再执行 commit。

## 一、本阶段完成内容

**数据库**

- 新增 `stations`（驿站）与 `shelves`（货架）两张表
- Alembic 迁移 `0002_create_stations_shelves`
- 唯一约束：`stations.code`、`(shelves.station_id, shelves.code)`
- 外键：`stations.manager_id → users.id`、`shelves.station_id → stations.id`

**后端接口（10 个）**

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/stations` | 驿站列表（含货架、容量、占用率） | 登录用户 |
| POST | `/stations` | 新增驿站 | 管理员 |
| GET | `/stations/{id}` | 驿站详情 | 登录用户 |
| PUT | `/stations/{id}` | 修改驿站 | 管理员 |
| PATCH | `/stations/{id}/status` | 启用 / 停用 | 管理员 |
| GET | `/stations/{id}/shelves` | 货架列表 + 驿站汇总 | 工作人员、管理员 |
| POST | `/stations/{id}/shelves` | 新增货架 | 管理员 |
| PUT | `/shelves/{id}` | 修改货架 | 管理员 |
| DELETE | `/shelves/{id}` | 删除空闲货架 | 管理员 |

业务规则：

1. 驿站编码全局唯一；负责人必须是工作人员或管理员。
2. 营业结束时间必须晚于开始时间。
3. 货架编号在驿站内唯一；容量 1—200。
4. 货架容量不能小于已用格口数；有包裹的货架不能删除或停用。
5. 驿站容量随货架增删改自动重算，取所有货架容量之和。

**演示数据**

- 东区驿站 `ST-A`：A-01 / A-02 / A-03 三个货架，共 84 个格口，负责人 staff01
- 西区驿站 `ST-B`：B-01 / B-02 两个货架，共 40 个格口
- 目前 `used_count` 均为 0，阶段三入库后开始累计

**前端**

- 新增「驿站管理」页面（管理员、工作人员可见）
- 顶部四张指标卡：驿站数量、货架数量、总格口、平均占用率
- 驿站卡片：编码、营业状态、地址、营业时间、负责人、占用进度条、货架编号
- 新增 / 编辑驿站弹窗：编码、名称、地址、电话、营业时间、负责人
- 货架管理抽屉：汇总数据 + 货架列表 + 新增 / 编辑 / 删除
- 工作人员只读：不显示新增、编辑、停用、删除入口，接口侧也会返回 403
- 沿用阶段一的 iOS 视觉与动效体系
